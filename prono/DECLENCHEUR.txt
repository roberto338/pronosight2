# Remplacer le mot de la PREMIÈRE ligne, puis commiter depuis l'éditeur web
# de GitHub. Le workflow « Moteur statistique » se déclenche tout seul et
# affiche son résultat dans l'onglet Actions.
#
#   rien           ne fait rien (état de repos, laisser ainsi après usage)
#   etat           lecture seule : combien de rencontres, combien d'équipes prêtes
#   backtest       note le modèle sur le passé (lecture seule)
#   sweep          cherche de meilleurs réglages, validation hors échantillon
#   audit          note les signaux déjà publiés par Victor (lecture seule)
#
# Le 1er de chaque mois, le workflow collecte et remesure tout seul, et
# n'ouvre une issue que si le gain devient significatif. Ce cron ne
# s'exécutera qu'une fois cette branche fusionnée dans la branche par défaut
# — GitHub ne planifie que depuis celle-ci.
#   backtest 10    idem, en n'incluant que les équipes à 10 matchs ou plus
#                  (le chiffre est le nombre de rencontres préalables exigé
#                   de CHAQUE équipe pour qu'un match soit notable)
#   apercu         simulation de la migration, aucune écriture
#   migration      applique la 014, régénère db/schema_neon.sql et le commite
#   backfill       collecte 90 jours de résultats
#   backfill 150   collecte 150 jours
#
# Un commit sur ce fichier vaut confirmation : l'éditer est un geste
# délibéré, contrairement à un menu déroulant qu'un pouce déclenche par
# accident. Remettre « rien » après chaque opération.
